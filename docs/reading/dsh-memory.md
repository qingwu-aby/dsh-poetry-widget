# 阅读笔记：dsh-memory（灵枢 LINGSHU）

> 仓库：https://github.com/FuRongJun-1999/dsh-memory （MIT，v0.9.14）
> 定位：模型之外的长期记忆基础设施——对话沉淀为纯 md 认知图，记什么/取什么/能不能写由确定性规则裁决，MCP 挂载，配套 Rust 检索、蜂群运行时、蜂巢并发、中文编译器与公开评测。
> 阅读时间：2026-10-26。目的不是照搬，而是判断哪些能力适合小鲸鱼、能让她更好；结论写在最后。

## 1. 它是什么（一句话版）

一个“白箱”记忆平台：写入过三道闸门、以 `committed` 确认成功、原文即真源、索引只是派生物；召回按重要性/条件/时间线/预算装包；遗忘只能显式发起；附带元认知（不确定标 BLINDSPOT）、审计、双实例互验与工程纪律。

## 2. 有价值的思想（与我们的现状对照）

| 灵枢的做法 | 对小鲸鱼是否适用 | 我们现在的状况 |
| --- | --- | --- |
| **原文即真源，索引是派生物** | 适用。她的 journal/learning-log 是只追加原文，topics/voice/index 都是派生 | 已经如此：append-only md/jsonl + topics/voice 派生，无静默删除 |
| **遗忘只能显式，不做静默淘汰** | 适用 | 已经如此：learned 话题超限进 `topics-archive.jsonl` 归档，可检索 |
| **相关性 + 预算装包（importance/budget/layered injection）** | 部分适用：不需要它那套“四层注入”，但“旧记忆按相关性被想起来”是她缺的 | 之前只取最近条目 + 话题关键词；**本轮借鉴**：新增「旧时回声」——从 24h 以前的 journal 里按关键词相关度挑 ≤2 条，确定性打分、有预算、只读 |
| **validity / 时效过滤** | 适用 | 之前 `experiencing` 一直显示为“最近”，可能把几天前的事当成眼下；**本轮借鉴**：36h 时效，过期不再注入 |
| **写入门禁 + `committed` 语义（绝不假装成功）** | 部分适用 | 我们有解析校验、原子写、model-errors 审计；但部分追加（learning-log/试探）没做“写后确认”。可做小改进，非本轮 |
| **元认知 / BLINDSPOT（不确定就标不确定）** | 精神适用，机制不适用 | 我们的 felt/自省本来就允许“说不好/不确定”，不需要单独标记文件 |
| **审计、可复现、双实例互验、工程纪律** | 方法论适用，基础设施不适用 | 我们已有单测 + append-only + 失败记录；双实例互验对单进程挂件过重 |
| **身份锚点（独立永久层，最多 3 条）** | **不适用** | 她的身份/声音是自生成、会变的（voice.json 自提炼）；固定“身份事实”会变成另一种静态文案池 |
| **MCP/Python 子进程、Rust 检索、蜂群/蜂巢、82 工具** | **不适用** | 挂件必须零安装、纯 Node、单用户、轻量；引入外部进程/工具面会破坏“她自己”的边界与可维护性 |
| **确定性裁决“能不能记”** | **不适用** | 她的记忆是模型写的感受/想法/试探，语义好坏无法用规则裁决；我们只做结构校验 + 追加 + 可回溯 |

## 3. 本轮实际借鉴（只取两小块，且是轻量版）

1. **旧时回声（相关性 + 预算装包的最小实现）**：`memory-recall.mjs` 新增 `recallEchoes`，从 24h 以前的 journal 条目里按关键词命中数打分，取 ≤2 条，进入记忆摘要的「你以前写下过的（旧时回声）」；确定性、只读、有上限，且不会和“最近想法”重复。目的：让她不只是记得最近几条，而是能被更早的相关记忆轻轻碰一下。
2. **时效（validity）**：`self-being.mjs` 给 `experiencing` 加 36h TTL；超过就不再当成“最近在体会”，避免旧事被摆在眼下。

## 4. 明确不做的

- 不引入 Rust 检索 / MCP 子进程 / Python 依赖：挂件保持零外部运行时。
- 不引入 swarm/hive/双实例互验/30+ 工具面：单用户小挂件，收益远小于复杂度与风险。
- 不把她的记忆改成“确定性规则裁决”：那会把 LLM 写的内在生活挤成规则表，也违背“她的想法来自她自己”的设定。
- 不加固定身份锚点：她的声音/状态是自生成且允许变化的；固定锚点 = 静态人设，和“不要静态文案池”的约定冲突。
- 不引入静默遗忘/自动清理：继续保持只归档、不删除（与灵枢的“显式遗忘”原则一致，但用的是更简单的归档方案）。

## 5. 一句话结论

灵枢值得学的不是它的基础设施，而是**把记忆当“存/取/裁决/时效/预算”分层的工程自觉**；对小鲸鱼，只取“相关性 + 预算地想起旧事”和“时效过滤”两小块，其余（MCP/Rust/蜂群/确定性裁判/身份锚点）都不适合也不该搬。
