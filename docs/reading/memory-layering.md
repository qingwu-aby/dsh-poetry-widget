# 阅读笔记：LLM Agent 的记忆分层（以及小鲸鱼怎么用）

> 目的：给“记忆太多会拖慢检索、又怕性格被稀释”找一个可行的分层方案。下面是论文线索、我取用的部分、以及**没有照搬**的部分。
> 记录时间：2026-10-26。实现见 `lib/memory-layers.mjs`（v1.71）。

## 1. 人类记忆的经典模型（设计的出发点）

- **Atkinson & Shiffrin (1968) 多存贮模型**：感觉记忆 → 短时记忆 → 长时记忆；短时记忆容量有限，需要复述/编码才能进长时。
- **Tulving (1972)**：把长时记忆分成**情景记忆**（发生了什么、何时何地）与**语义记忆**（知道什么、概念与事实）。
- **McClelland, McNaughton & O'Reilly (1995) 互补学习系统（CLS）**：海马快速记具体经历，皮层慢慢把重复出现的结构整合成概括；两套系统互补，避免新记忆直接覆盖旧知识。
- **Ebbinghaus (1885) 遗忘曲线 / Squire (2004) 记忆系统**：遗忘与巩固都是记忆系统的一部分；“记住什么”和“记得多牢”本身是分层的。

对我们的含义：**不要把全部记忆塞进同一个上下文池**；具体经历（情景）与提炼出来的“我知道/我是谁”（语义/自我）要分开；整合应该像睡眠一样在后台慢慢发生，而不是每次对话都重算。

## 2. LLM Agent 记忆工作的可取之处（论文线索）

| 论文 | 核心做法 | 我们取用的点 |
| --- | --- | --- |
| MemGPT: Towards LLMs as Operating Systems（arXiv:2310.08560） | 把上下文当“主存”，外部存储当“磁盘”，用分页/中断在主上下文与外部记忆之间换入换出 | “上下文是预算、记忆在外部”的基本立场；我们不做分页，只做固定预算的分层注入 |
| MemoryBank（arXiv:2305.10250） | 长期记忆 + 基于遗忘曲线的回忆/强化，另有人格画像 | 记忆会衰减/强化，但**我们不删除**，只做“压缩成概括 + 保留原文” |
| Generative Agents（arXiv:2304.03442） | memory stream + 按 recency/importance/relevance 检索 + reflection 生成更高层记忆 | 检索三要素（新近、重要性、相关性）与“反思产生更高级记忆” |
| MemoryOS（arXiv:2506.06326）、MemOS（arXiv:2507.03724） | 短/中/长多层记忆、热度更新、调度 | 短/中/长分层的思路；我们不引入复杂调度器 |
| HippoRAG（arXiv:2405.14831） | 海马索引 + PageRank 做多跳检索 | “索引是派生物”的立场；我们不建图索引 |
| A-MEM（arXiv:2502.12110） | 笔记式记忆，自动建链接/演化 | 记忆条目可以带元数据；暂不做自动链接 |
| RecMem（arXiv:2605.16045）、TRUSTMEM（arXiv:2606.25161） | 递推式/可信的记忆整合 | 整合要保守：坏结果不落盘、原文不动 |
| “My agent understands me better”（arXiv:2404.00573） | 类人回忆与巩固 | 用“回忆”而不是“数据库查询”的口吻写摘要 |
| PGMem（arXiv:2608.01708）、SYNAPSE（arXiv:2601.02744） | 人格-记忆紧耦合 / 情景-语义扩散激活 | 自我/人格层要独立、稳定，不被大量情景稀释 |
| Not All Memories Are Equal（arXiv:2609.30289）、Hierarchical Memory for High-Efficiency Long-Term Reasoning（arXiv:2507.22925） | 分层 + 有效性/预算感知的检索 | 检索必须带预算上限，且区分“仍然有效”的记忆 |

## 3. 小鲸鱼的分层设计

| 层 | 内容 | 写入 | 读取 |
| --- | --- | --- | --- |
| L0 工作记忆 | 此刻的 felt、在体会、最近心情、当前行为 | 自处循环实时写 | 每次自处/碎碎念直接注入 |
| L1 情景记忆 | `journal.jsonl` 里的逐条碎碎念/心情/自省（原文） | 只追加，不删除 | 最近若干条 + 关键词/回声检索 |
| L2 整合记忆 | `memory-layers.json`：每 1–2 天把“两天前的零碎记忆”整合成一段**她自己的回忆概括**（episode） | 每天一次，模型写、失败不落盘 | 按关键词相关性取 ≤2 段；无命中给最近 1 段 |
| L3 自我/性格层 | 同文件里的 `selfFacts`：她“越来越清楚、一直成立”的短句（喜欢什么、怎么做事、在意什么） | 从整合结果里提炼，去重、只增不减 | **每次碎碎念都注入（≤6 条）**，不参与淘汰 |
| 档案层 | 原文永远保留：journal、learning-log、topics-archive、feelings… | 只追加/归档 | 需要时按关键词回查 |

**检索预算**：碎碎念的 memory digest 仍是确定性规则（不调用模型），各段落都有条数上限；selfFacts 与最近回忆概括进入同一份 digest，总长度受已有 80 字/条与条数上限约束，不随记忆总量线性增长。**所以记忆变多不会让上下文变慢**——检索只看最近条目、关键词命中的旧概括、以及少量自我短句。

**为什么这样能帮性格成型**：情景记忆回答“发生过什么”，自我短句回答“我是谁”；后者只从多次经历里慢慢提炼、单独注入、不会被大量新记忆冲淡。风格上她仍用自己的话写，不做“人格打分”。

## 4. 明确不做的

- 不做向量数据库/图索引/Rust 检索：当前规模用 JSONL + 关键词打分足够，避免重依赖。
- 不做静默遗忘：原文不删除；只做概括与归档（延续之前的“只归档不删除”原则）。
- 不把检索交给 LLM 判断：检索是确定性规则（关键词 + 新近 + 预算），模型只在**整合**时写回忆。
- 不做“人格分数”或强制人设：selfFacts 是她自己写的短句，可被后续整合补充，不是外部设定。

## 5. 一句话结论

分层不是为了“记得更多”，而是为了让**具体经历、概括、自我**各归其位：原文留档、概括供检索、自我短句做锚。这样记忆越多，检索仍是有预算的；性格反而因为有一层慢慢沉淀的“我是谁”而更稳。
