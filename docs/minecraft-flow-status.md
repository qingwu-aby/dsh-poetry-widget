## Wiki 读取量（2026-11-24 调整后）

之前的坑：先按 6000 字截断再去选小节，长页的“用法”被切掉；只挑 2 节，喂给模型几十字。

## 解析容错（2026-11-25）

近 3 小时 312 次决策里有 17 次（5.4%）落在「模型没有给出合法工具」。

原因：原来只取回复里**第一个 `{` 到最后一个 `}`** 做 JSON.parse，
模型一旦把解释文字、代码块或多个对象混在一起，整段就解析失败。

现在改成括号配平扫描（`minecraft-parse.mjs`）：

- 跳过字符串内的括号与转义；
- 逐个尝试候选对象，取第一个 tool 合法的；
- 前面有坏 JSON 也能解析后面的合法命令。

示例：`我先想想 {不是json} 然后 {"tool":"mc_wait",...}` → 仍能正确得到 mc_wait。

## 失败时自动带知识（2026-11-26）

## 假小屋：验收只看“不是空气”（2026-11-26 中午）

现场逐格读回（-53,69,-21）：

```text
内部(脚)=air 内部(头)=air
墙E=air  墙W=dirt  墙N=leaf_litter 墙S=air
屋顶=air
```

三面漏风、没有屋顶，但系统给了 `verified: {walls:14, roof:7}`。

原因：验收只判断“不是空气”，所以挖进山坡时天然土层/树叶被当成墙和屋顶。

修复三步：

1. 先**清空内部**（放置回退有时会把方块塞进屋里），否则“能站人”永远是 false；
2. 改成**从内部判断**：脚上方四向是否都有方块（≥3 面算有墙）、头顶是否有盖、脚下方是否能站；
3. 门与材质也要对得上（`fill` 材质，或 `_door`）。

创造世界实测：

```text
验收：四面有墙 4/4、头顶有盖 有、能站人 是、门 已装。
SHELTER3 OK 小屋搭好了（四面有墙 4/4、头顶有盖、能站人、门 已装）
```

同时删掉了指向假小屋的 `shelter-mark.json`。

## 环境感知：从“加提示”转向“改感知”（2026-11-26 午）

用户指出“再加条件提示不是长久之计”——对。根源是她的感知里缺“我在什么环境里”，
所以只能用提示替她补。

改法：**把环境变成观测字段**，而不是特殊情况下多一句话。

bot 每次观察都算：

```text
situation = {
  walls: 四个方向头顶那格有几个实心方块,
  roof: 头顶 2~3 格有没有实心方块,
  skyExposed: 头顶方块的 skyLight 是否 = 15（能见天）,
  enclosed: walls>=3 && roof,
  onGround: 脚下是否实心
}
```

World 在**位置行**里渲染成事实（不是建议）：

```text
位置：-14.7,69,54.5（露天）；血量 20/20；饥饿 20/20；时间 夜晚。
位置：20.2,64,22.5（有顶有墙）；…
```

实测（创造世界，露天）：

```text
walls 0 roof false skyLight 15 → enclosed false | skyExposed true   ✓ 判为“露天”
```

好处：

- 不新增提示类别，不按条件判断“要不要说”；
- 她说的“我在庇护所里”如果与环境不符，位置行本身就是反证；
- 对“地下/屋内/露天”三类都有事实描述。
