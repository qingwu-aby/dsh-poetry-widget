# 小鲸鱼 v2 任务计划

> 依据：`docs/architecture-v2.md`、近几轮对模型闸门/任务监管/记忆增长/可观测性的瓶颈分析。
> 原则：先加固地基，再收 Activity；不重写现有 domain；每阶段保持测试和检查绿。

## 0. 当前基线

- 现有架构：kernel / composition / 14 个 domain / client / 独立 Minecraft 进程；
- 测试 586 条，`npm run check` 通过；
- 已有：Minecraft World、工具/回执/打断、文件化 + Git 游戏记忆、插件设置页、token 上限配置；
- 已知瓶颈：模型闸门仅 2 并发且队列无上限、心跳任务无租约/超时、无 Task 抽象、记忆/备份 234M、日志无轮转、无指标。

## 1. 阶段与任务

### Sprint 0：地基加固（必须先做）

| ID | 任务 | 交付物 | 验收 |
|---|---|---|---|
| H1 | 模型网关加固 | 可配置并发、队列上限、排队超时、按角色预算、异步批量预算写盘 | 慢调用不会无界堆积；队列满时明确拒绝；`health` 可见队列深度 |
| H2 | 任务监管骨架 | Task 租约、心跳、超时、取消、幂等键 | 长任务可被强制结束；重启不重复执行 |
| H3 | 可观测性 | traceId、任务/模型/事件指标、日志轮转、成本统计 | 一次任务可串起事件→模型→工具→回执 |
| H4 | 记忆与日志治理 | journal/backups 保留策略、归档、索引；日志大小上限 | 234M 可降到可控范围；检索不随历史线性变慢 |
| H5 | 基线压测 | 并发/长任务/模型故障/重启测试脚本 | 形成基线报告，后续每阶段对比 |

**依赖**：H1/H2 可并行；H3/H4 与 H1/H2 并行；H5 最后。

### Sprint 1：Hub Core

| ID | 任务 | 交付物 | 依赖 |
|---|---|---|---|
| C1 | Event Bus | 命名空间、只追加、订阅、回放、保留窗口 | H3 |
| C2 | Task Board | 状态机、优先级、成功标准、等待/阻塞、幂等 | H2 |
| C3 | Scheduler | 单前台、后台低优先级、抢占/恢复、预算 | C1, C2 |
| C4 | Activity Registry | manifest、启停、健康、权限、资源声明 | C1 |
| C5 | Control API | tasks/activities/events 只读与控制端点 | C2, C3 |

**验收**：同一时刻只有一个前台 Task；暂停/恢复/打断可用；事件可回放。

### Sprint 2：Memory / Feedback

| ID | 任务 | 交付物 | 依赖 |
|---|---|---|---|
| M1 | Memory Gateway | 唯一读写入口；事件/情景/语义/方法/愿景 | C1 |
| M2 | Feedback Ledger | 假设→实验→回执→结论→方法 | M1 |
| M3 | 先接只读 | journal / game-memory / methods 只读接入 | M1 |
| M4 | 再切写入 | 各域写入逐步改走 Gateway；保留旧接口兼容 | M3 |

**验收**：所有 Task 结束有 feedback；长期记忆无直接旁路写入。

### Sprint 3：World 迁移

| ID | 任务 | 交付物 | 依赖 |
|---|---|---|---|
| W1 | Chat World | 消息事件、回复工具、抢占、回执 | C3, M1 |
| W2 | Minecraft World | `game-world` 收进 Hub，工具/回执/中断统一 | C3, M1 |
| W3 | World 隔离 | 独立进程/健康/崩溃重启；互不直接依赖 | C4 |
| W4 | 验证器 | 每个工具回执可验证事实；失败进 Feedback | M2 |

**验收**：杀掉 Minecraft 不影响聊天；反之亦然。

### Sprint 4：新 Activity

| ID | 任务 | 交付物 | 依赖 |
|---|---|---|---|
| A1 | Reading | 打开/翻页/高亮/笔记/卡住事件 | W1-W3 |
| A2 | Video | 观看/摘要/主题事件；可复用 dsh-bili-scroll | W1-W3 |
| A3 | Study/Research | 问题→资料→假设→验证→方法 | A1/A2 |
| A4 | Activity SDK | `defineActivity`、manifest 校验、设置页活动管理 | C4 |

**验收**：新 Activity 只注册 manifest 即可出现，不改 Hub 核心。

### Sprint 5：控制面

| ID | 任务 | 交付物 | 依赖 |
|---|---|---|---|
| U1 | 模型/推理面板 | provider/model、角色 effort、token、fallback、测试连接 | C5 |
| U2 | Task 控制台 | 当前/排队/暂停/恢复/最近回执 | C5 |
| U3 | 记忆浏览器 | 查看/编辑/导出/重建索引 | M1 |
| U4 | CLI/API | tasks/models/activities/memory/training | C5, M1 |

### Sprint 6：训练旁路

| ID | 任务 | 交付物 | 依赖 |
|---|---|---|---|
| T1 | 数据集导出 | 按活动/主题/时间导出；清洗/脱敏 | M1 |
| T2 | 训练配置 | 基座/adapter、rank/steps/lr、确认、预算、取消 | U1 |
| T3 | 评估闸门 | 语气/回归/安全评估；candidate 不直接上线 | T2 |
| T4 | Promote/Rollback | candidate→live、回滚、状态页 | T3 |

**原则**：训练不阻塞在线 Task；不直接写长期记忆；默认关闭。

### Sprint 7：清理与验收

| ID | 任务 | 交付物 |

| F3 | 鲁棒性验收 | 并发、中断、重启、模型故障、训练旁路 |

```text
H1 ─┐
H2 ─┼─→ C1 ─→ C2 ─→ C3 ─→ W1/W2 ─→ A1/A2/A3
H3 ─┤        └─→ C4 ─────────────┘
H4 ─┘
H5 ─────────────────────────────────→ F3

M1 ─→ M2 ─→ M3 ─→ M4 ─→ A1/A2/A3
C5 ─→ U1/U2/U3/U4

```

可并行：H1/H2/H3/H4；M1-M4 与 C1-C4 并行；A1/A2 与 U1/U2 并行。

## 3. 不建议现在做

- 不重写 2.9 万行 domain；
- 不把每个 domain 都改造成 Activity；
- 不用本地模型训练来替代规划/工具校验；
- 不做无上限并发的 Activity；
- 不在训练管线未隔离前开放自动训练。

## 4. Definition of Done

- 单前台 Task、单模型调用，队列有界；
- 所有工具调用有回执，所有 Task 有 feedback；
- 活动间 0 直接依赖，崩溃可隔离；
- 记忆唯一写入口，可审计/可回滚；
- 模型/训练/任务/记忆有用户可改的界面或 API；
- 压测、故障注入、重启恢复通过。

# v2.1 遗漏检查与补充

原计划主要覆盖“架构/功能/迁移”，漏了 **安全、数据生命周期、幂等/补偿、外部内容信任、多会话、成本治理、运维发布** 这些跨领域事项。补充如下。

## 5. 必须补的跨领域任务

| ID | 领域 | 任务 | 为什么不能漏 | 优先级 |
|---|---|---|---|---|
| SEC-1 | 安全 | 威胁模型 + Activity 权限模型（文件/网络/模型/工具） | Activity 是可扩展代码，默认不可信 | P0 |
| SEC-2 | 安全 | API token 轮换、路由限流、密钥/配置不进日志 | 外部 API 一多，token 就是边界 | P0 |
| SEC-3 | 信任 | 外部内容（网页/视频/书）prompt injection 防护 | 她主动上网，内容不能当指令 | P0 |
| SEC-4 | 隐私 | 数据导出/删除/审计；聊天/游戏/训练数据边界 | 用户会问“我的数据在哪” | P1 |
| DATA-1 | 数据 | state schema 版本、迁移、回滚 | 当前 28M 状态 + 234M agent-memory 已有历史债 | P0 |
| DATA-2 | 数据 | 备份/恢复演练、保留策略、磁盘上限 | 只有备份没有恢复等于没有 | P0 |
| DATA-3 | 一致性 | 任务幂等键、事件去重、副作用补偿 | 重启/重放会重复放方块/发消息 | P0 |
| EVT-1 | 事件 | 事件 schema 版本、未知事件保留、回放兼容 | 扩展 Activity 后事件格式会演进 | P1 |
| EVT-2 | 事件 | 背压、保留窗口、归档、重放上限 | 事件日志无界会长成第二个 journal | P0 |
| MULTI-1 | 运行时 | 多会话/多页面隔离（状态、任务、模型预算） | 现在多处是全局状态 | P0 |
| COST-1 | 成本 | 模型 token 上限、每日预算、告警、按活动配额 | 默认不封顶后成本不可控 | P0 |
| COST-2 | 可用性 | provider 故障切换、任务中途换模型、降级 | 单 provider 挂掉不能全停 | P1 |
| QUAL-1 | 记忆质量 | 去重、冲突、过期、来源/可信度、防污染 | 错误方法会被 feedback 放大 | P1 |
| QUAL-2 | 评估 | 任务成功率/延迟/恢复时间基准；回归集 | 没有基线无法判断升级是否退步 | P0 |
| ACT-1 | 扩展 | Activity SDK 沙箱、资源配额、版本兼容 | 动态 Activity 是最大攻击面 | P0 |
| ACT-2 | 扩展 | 活动启停、权限、健康、崩溃重启 UI | 用户要能一键停掉某个活动 | P1 |
| UX-1 | 控制 | 全局暂停/急停、活动与任务状态、审计 | 出问题要能立刻停 | P0 |
| UX-2 | 注意力 | 安静时段、用户活动让位、通知策略 | 多活动会打扰用户 | P1 |
| UX-3 | 可访问性 | 键盘/屏幕阅读/字号/多语言 | 设置页与控制台是长期界面 | P2 |
| MC-1 | 世界稳定性 | 服务器/进程生命周期、世界备份、崩溃恢复 | 游戏进程最容易崩/卡 | P0 |
| MC-2 | 世界安全 | 防重复 bot、防拆玩家建筑、世界边界 | 自主活动必须有硬边界 | P0 |
| OPS-1 | 运维 | SLO、指标、告警（队列/磁盘/模型失败/掉线） | 现在只能翻日志 | P0 |
| OPS-2 | 运维 | 日志轮转、磁盘/内存上限、夜间清理 | 日志和备份会慢慢吃满盘 | P1 |
| OPS-3 | 发布 | 升级/回滚、DSH 宿主兼容、迁移演练 | 插件升级不能靠手改 | P1 |
| TRAIN-1 | 训练 | 训练数据同意/许可、隐私清洗 | 用聊天/书/视频训练有版权与隐私风险 | P0 |
| TRAIN-2 | 训练 | 评估集、回归、promote/rollback（原 T3/T4） | 没有闸门不能上线 | P0 |
| TEST-1 | 测试 | 长稳（soak）、故障注入、重启恢复 | 单元测试覆盖不了运行鲁棒性 | P0 |
| TEST-2 | 测试 | 多会话并发、事件重放、磁盘满/模型超时 | 上述风险要有可重复验证 | P0 |

## 7. 决策门（不满足不进入下一阶段）

- **Gate A**：模型队列有界、任务可超时/取消、恢复演练通过；
- **Gate B**：单前台 Task，事件可重放，副作用不重复；
- **Gate C**：所有写入经过 Memory Gateway，冲突/来源可追溯；
- **Gate D**：任意 Activity 崩溃不影响 Hub；权限/配额生效；
- **Gate E**：训练候选经过评估与回滚演练；数据许可/隐私确认；
- **Gate F**：soak/故障注入/升级回滚通过。

## 8. 任务计划字段补充

每个任务除了目标/交付物/依赖，还应带：

```text
priority: P0/P1/P2
owner: unassigned
estimate: S/M/L
risk: low/medium/high
rollout: feature-flag / dark-launch / direct
observability: 指标/日志/告警
rollback: 如何撤回
test: 单测/契约/e2e/load/chaos
```

## 9. 结论

原计划不缺“功能任务”，缺的是**跨领域的非功能任务**：安全、隐私、数据恢复、幂等、背压、成本、多会话、发布、长期稳定性。建议把上述 SEC/DATA/EVT/COST/QUAL/ACT/UX/MC/OPS/TEST 任务并入各 Sprint，并在每阶段设置 Gate；否则 Hub 功能做完后仍可能出现“功能可用但不敢长期开”的状态。
